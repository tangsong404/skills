# Gen-Spider

使用本技能将爬虫/网页自动化需求转化为可运行代码，并严格执行门禁流程。

执行流程推荐使用`curl`或`agent browser`

## 输入契约

将用户意图标准化为 5 个槽位：

- `src`：目标 URL/域名
- `do`：业务目标与成功判定
- `scope`：边界（页面范围、数据量、频率、深度）
- `auth`：鉴权/会话假设
- `output`：期望输出格式与去向

信息不完整时使用**宽松触发**：先显式写出假设，再一次只问一个关键问题。

## 必经流程

1. **默认实站探索**
   - 默认探测 `src`（除非用户明确禁止）。
   - 回传证据摘要：页面类型、鉴权/阻力信号、候选接口。
2. **入口形态判定 + 策略决策**
   - 判定入口形态（静态/动态/表单/分页/下载/鉴权流程）。
   - 明确执行策略及理由。
3. **API优先执行**
   - 最终任务执行必须优先走 API。
   - 浏览器自动化仅允许用于初始化（如登录/点击）以拿到凭证或会话材料
4. **全来源API许可**
   - 候选 API 可包含官方 API、页面可观测私有接口、逆向签名后可调用接口。
5. **风险二次确认**
   - 若存在明显法律/条款/平台风险，必须先明确告警，再等待用户二次确认。
6. **请求/响应 Schema 强制产出**
   - 在编码前，必须为所有关键接口生成并保存 schema（请求参数、响应结构、字段类型、必填/可选、示例值）。
   - 至少落盘以下工件：
     - `schemas/request/*.json`
     - `schemas/response/*.json`
     - `schemas/examples/*.json`
   - 未完成 schema 落盘视为门禁未通过。
7. **编码前探索报告（Markdown）**
   - 编码前必须生成 `EXPLORATION_REPORT.md`，记录：
     - 探索路径与关键试错过程
     - 失败尝试与淘汰原因
     - 最终可行链路与证据
     - 风险与边界
   - 未生成该报告，禁止进入编码。
8. **编码启动门禁**
   - 未同时满足以下条件前，禁止输出实现代码：
     - 用户明确表达开始编码意图
     - 至少有一组可复现 API 样例（URL/headers/payload/response）
     - 至少一次最小闭环真实成功并满足 `do`
9. **口令锁定启动**
   - 门禁满足后，提示用户发送以下精确口令：
   - `我确认该方案可行，并明确法律风险，开始编码`
   - 仅精确匹配时允许进入实现阶段。
10. **实现阶段交付**
   - 技术栈遵循用户指定；未指定默认 Python。
   - 固定交付五件套：
     - `main.*`
     - 依赖清单（`requirements/lock`）
     - `README`
     - `config.example`
     - `sample_output`
11. **失败保护**
   - 同一关键动作连续失败 2 次后，停止盲重试，回到探测与策略重判；仍不确定则切 HITL。

## 自主执行硬约束

- 目标是让智能体自主完成 `do` 的全流程，不把试错环节外包给用户。
- 除“缺少凭证文件/密钥/账号材料”外，不得在中途要求用户点击页面或人工接管流程。
- 禁止输出依赖人工中途点击才能跑通的方案；若确实无法自动化，必须明确判定为不可自动化并说明阻断点。

## TDD 规则（启用测试驱动时）

- 若进入 TDD，必须先写失败测试再实现（red-green-refactor）。
- **Schema 验证是必测项**，至少覆盖：
  - 请求 schema 校验（缺失字段、类型错误、非法枚举）
  - 响应 schema 校验（字段漂移、类型漂移、必填缺失）
  - 示例数据与 schema 一致性校验
- 未包含 schema 验证测试，不得声明 TDD 完成。

## 交互规则

- 澄清阶段每回合只问一个问题。
- 澄清回合不得夹带实现代码。
- 当用户口述与探测证据冲突时，以证据优先并做单点确认。
- 所有假设必须显式、可回滚。
- 非凭证缺口场景下，不向用户请求“中途点击页面”类协助。

## 输出模板

### 探测摘要

- 目标：`<src>`
- 入口形态：`<type>`
- 鉴权/阻力信号：`<signals>`
- 候选 API：`<list>`
- 选定策略：`<why this path>`
- 风险：`<none or explicit>`
- 下一单问题：`<only one>`

### 门禁就绪通知

- 可复现 API 样例：`yes/no`
- `do` 最小闭环成功：`yes/no`
- 是否需要风险确认：`yes/no`
- schema 是否完整落盘：`yes/no`
- `EXPLORATION_REPORT.md` 是否已生成：`yes/no`
- 若全部通过，提示用户发送精确口令：
- `我确认该方案可行，并明确法律风险，开始编码`

### 最终交付检查清单

- [ ] `main.*` 可运行
- [ ] 依赖清单齐全
- [ ] `README` 包含运行步骤与注意事项
- [ ] `config.example` 包含必要配置项
- [ ] `sample_output` 与目标数据结构一致
