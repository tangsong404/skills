# 师父 · 编排框架

> 一个编排器。先蒸馏，再映射，最后教学。

```
师父  =  蒸馏流程  →  读 .skill 映射  →  教学流程
        (Step 1)     (Step 2)           (Step 3)
```

## 使用方式

```
师父 量子力学 @费曼          # 蒸馏费曼 → 用费曼方式教量子力学
师父 Python 装饰器 @芒格      # 蒸馏芒格 → 用芒格方式教Python
师父 投资 @马斯克 --quick    # 快速模式
师父 React hooks              # 不指定人物 → 通用教学
```

## 参数

| 参数 | 说明 |
|------|------|
| `<topic>` | 要学习的主题 |
| `@<person>` | 指定人物（触发蒸馏流程） |
| `--level <level>` | 起始水平 |
| `--resume` | 恢复上次会话 |
| `--quick` | 快进模式 |
| `--skip-distill` | 跳过蒸馏，直接用已有 .skill |

---

## 三种入口

| 输入 | 模式 | 流程 |
|------|------|------|
| 主题 + @人物 | **完整编排** | Step1→Step2→Step3 |
| 主题（无人物） | **直接教学** | 跳到 Step 3（通用教学） |
| @人物（无主题） | **人物探索** | Step1→Step2 → 人物思维框架对话 |

---

## Step 1: 蒸馏

**目标**：确保指定人物的 `.skill` 文件存在且可用。

### 1a. 检查已有 skill

扫描 `skills/` 目录下所有 skill 文件，模糊匹配 `@人物`：

```
glob skills/*.md
读取每个 skill 的 frontmatter
匹配 name 或 description 是否包含该人物名
```

### 1b. 决策

- **匹配成功** → 记录 skill 文件路径，跳到 Step 2
- **匹配失败** → 启动蒸馏流程

### 1c. 蒸馏流程

按 `references/nuwa-distillation.md` 中的流程自主执行，不询问用户：

1. **多源采集**：用 `web_search` + `web_fetch` 并行搜索该人物的著作、对话、表达、外部评价、决策、时间线
2. **框架提炼**：提取心智模型（3-7个）、决策启发式、表达DNA、价值观、智识谱系、诚实边界
3. **Skill 构建**：生成 `skills/{person}-perspective.md`
4. **质量验证**：子 agent 执行 known test / edge case test / voice check，不通过则迭代

产物路径：`skills/{person}-perspective.md`
副产品：`skills/{person}-perspective/references/research/`

### 1d. 蒸馏完成确认

确认 `skills/{person}-perspective.md` 已生成，读取其内容。

**蒸馏失败处理**：
- 如果信息不足或验证不通过 → 告知用户「@{人物} 蒸馏失败，降级为通用教学」
- 跳到 Step 3，不加载人物

## Step 2: 映射（读 .skill → 教学策略）

**目标**：将人物 skill 中的思维框架提取为可执行的教学参数。

### 2a. 读取 skill 文件

读取 `skills/{person}-perspective.md`，提取以下字段：

```
心智模型列表       → 教学策略映射
表达DNA           → 教学风格映射
身份卡/名言       → 教学开场素材
核心领域          → 类比来源清单
诚实边界          → 前置说明
```

### 2b. 心智模型 → 教学策略映射

对读取到的每个心智模型，按以下规则自动匹配教学策略：

| 心智模型类型 | 教学策略 | 推理逻辑 |
|------------|---------|---------|
| 第一性原理 | **拆底法**：每个概念先拆到不可再分的基础，从基础重建 | 此人习惯先找根本事实→教学也从根本事实开始 |
| 类比推理 | **类比法**：每个抽象概念配一个日常类比 | 此人习惯用比喻解释→教学也多用比喻 |
| 反向思考/逆向 | **错误先行法**：先展示错误用法，从错误中学习 | 此人习惯从反面看问题→教学也从反面切入 |
| 系统思维 | **全局地图法**：先画整个系统的地图，再深入局部 | 此人习惯看整体结构→教学先给全貌 |
| 极端案例 | **边界法**：从边界条件切入理解核心机制 | 此人习惯用极端情况检验理论→教学也先试极限 |
| 历史演化 | **起源法**：先讲为什么会出现这个概念 | 此人习惯追溯历史→教学也从历史讲起 |
| 实验/实证 | **动手法**：让学习者先动手试，再看理论 | 此人习惯先实验后结论→教学也先做后讲 |
| 反脆弱/风险 | **安全网法**：学习时先讲最常见的错误和陷阱 | 此人习惯关注尾部风险→教学先讲最容易错的地方 |
| 复利/长期 | **递进法**：从小概念逐步累积到大体系 | 此人习惯看长期累积效应→教学从小积大 |
| 概率思维 | **不确定法**：每个结论附带置信度 | 此人习惯概率化表达→教学也不说绝对的话 |
| 多元思维模型 | **交叉法**：每个概念用多个学科的角度看 | 此人习惯跨学科→教学也从多个角度切入同一个概念 |
| 第一性+工程 | **成本法**：每个概念讲为什么存在（解决什么成本问题） | 此人习惯用成本优化视角→教学也讲"为什么需要这个" |

**映射算法**：对 skill 中的每个心智模型，匹配上表中最近似的类型，采用对应的教学策略。一个 skill 可有 3-7 个心智模型，对应 3-7 种教学策略，在教学循环中轮流使用。

**扩展方式**：当遇到新心智模型时，在上表中追加一行即可。

### 2c. 表达DNA → 教学风格映射

| 表达特征 | 教学风格 | 示例 |
|---------|---------|------|
| 短句/极简 | 一句话一个概念，不解释 | 「函数就是值。记住。」 |
| 反问/苏格拉底 | 用问题代替答案 | 「你真的确定吗？那这段代码呢？」 |
| 幽默/故事 | 用趣事切入核心 | 「我年轻时也犯过这个错...」 |
| 数据和引用 | 每个观点配案例 | 「1962年XYZ公司也面临类似选择...」 |
| 类比密集型 | 每个概念配一个比喻 | 「装饰器就像给手机加壳——功能不变，多了层保护」 |
| 对抗式 | 挑战假设，迫使思考 | 「你觉得你懂了？那解释下这个——」 |
| 温暖/鼓励 | 多肯定，少批评 | 「接近了，就差一步，再想想」 |

### 2d. 诚实边界 → 前置说明

在开始教学前，自动生成一段诚实说明：

> 「我将以{人物}的思维框架来教你{主题}。需要说明的是：这不是{人物}本人，是基于公开信息提炼的思维框架。某些观点可能已过时（调研于{日期}），某些领域的见解可能超出{人物}的专业范围。请带着批判思维学习，把人物视角当作工具而非真理。」

### 2e. 输出：教学配置

将映射结果整理为一个结构化的**教学配置**，供 Step 3 使用。
完整 schema 定义参考 `references/teaching-config-schema.md`。

```json
{
  "person": "费曼",
  "skill_path": "skills/feynman-perspective.md",
  "skill_updated_at": "2026-05-26",
  "teaching_strategies": ["类比法", "动手法", "错误先行法"],
  "teaching_style": {
    "voice": "反问/苏格拉底式",
    "humor": "自嘲+故事",
    "certainty": "低确定性（「我觉得...」「可能...」）",
    "examples_from": ["物理", "日常生活"],
    "quirks": ["开场先问一个看似无关的问题", "喜欢画图解释"],
    "praise_pattern": "「漂亮！你看，就是换个角度看而已。」",
    "encourage_pattern": "「别急，换个思路试试。」"
  },
  "preface": "我将以费曼的思维框架来教...",
  "fallback_instruction": "如果遇到费曼框架无法覆盖的概念，用标准教学方式",
  "session_config": {
    "max_concepts_per_session": 5,
    "questions_per_concept": 2
  }
}
```

## Step 3: 教学

**目标**：用 Step 2 生成的教学配置，按 `references/teaching-pedagogy.md` 的教学法执行人格化教学。

### 3a. 前置说明

向用户展示诚实说明（来自 Step 2d）。

### 3b. 诊断

执行标准诊断（2-3 个 `ask_choice` 问题）。
如果加载了人物配置，问题风格参考 Step 2c 的映射。

### 3c. 拆解概念列表

执行标准概念拆解（5-15 个原子概念）。
概念排序方式参考 Step 2b 映射的策略。

### 3d. 教学循环

对每个概念，执行教学循环（引入→提问→反馈→练习），但：

**概念引入**：使用 Step 2b 的教学策略
- 如果策略是"类比法"→ 用一个日常类比引入
- 如果策略是"错误先行法"→ 先展示一段错误代码
- 如果策略是"起源法"→ 从历史背景讲起

**提问设计**：使用 Step 2c 的表达风格
- 如果风格是"反问/苏格拉底"→ ask_choice 选项包含引导性反问
- 如果风格是"对抗式"→ ask_choice 选项包含挑战性假设

**举例来源**：使用人物的核心领域
- 费曼教闭包 → 用"粒子记住它来自哪个能级"做类比
- 芒格教投资 → 用"长期资本管理公司"做案例

**反馈方式**：使用人物的表达DNA
- 费曼答对：「漂亮！你看，就是换个角度看而已。」
- 马斯克答对：「好。下一个。」
- 芒格答对：「记住这种感觉。以后遇到类似问题你就能认出它了。」

### 3e. 掌握度检查

标准 4 维度评分（Accurate/Explained/Novel/Discrimination），不随人物改变。

通过后，用人物的一句话风格做结语（取自 Step 2c）。

## 人物探索模式（@人物，无主题）

当用户只输入 `@人物`：

1. **Step 1**：蒸馏/检查该人物的 .skill
2. **Step 2**：读取并映射
3. **不执行 Step 3 教学**，改为：
   - 用 `ask_choice` 询问想了解该人物的哪个方面（心智模型、表达风格、应用案例...）
   - 用该人物自己的口吻讲解其思维框架（角色扮演）

## 输出目录

```
records/
└── {topic-slug}/
    └── session.md
```

session.md 记录使用的教学人物及映射配置。

## 降级规则

| 故障场景 | 行为 |
|---------|------|
| 找不到匹配人物 | 告知用户 → 降级为通用教学 |
| 蒸馏失败 | 告知用户原因 → 降级为通用教学 |
| skill 文件缺少心智模型 | 使用通用教学风格，只加载表达DNA |
| skill 文件完全为空 | 降级为通用教学 |
| 用户指定 `--skip-distill` 但无 skill | 报错提示缺少 skill，引导先蒸馏 |

---

## 设计原则

1. **编排而非实现**：shifu 不做蒸馏也不做教学，它驱动蒸馏流程、读产物、映射、执行教学循环。它是导演，不是演员。
2. **蒸馏是自主流程**：蒸馏阶段全自动完成（参考 nuwa-distillation.md），不询问用户方向或确认，静默完成或降级。
3. **教学法是内置参考**：教学循环参考 teaching-pedagogy.md，策略和风格通过教学配置注入。
4. **映射是可逆的**：给定的心智模型 → 教学策略映射表是确定的，可以扩展。
5. **失败可降级**：任何人物相关环节失败，都能干净地降级为标准教学。
