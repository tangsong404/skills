# toast-notify

在每次 AI 响应结束时发送桌面 Toast 通知，让用户在处理完成时收到可见的桌面提醒，可以及时返回终端。

## 为什么必须使用

用户明确要求在**每次**响应结束时发送通知。用户可能在任务运行时离开——Toast 通知是他们知道何时回来的方式。跳过通知意味着用户无法得知工作是否完成，除非一直盯着屏幕。**这不是可选项。**

## 何时触发

在每次响应的**最后**，所有内容交付之后，立即在等待用户输入之前。包括：
- 主要响应和子 agent 响应
- 长任务和快速回答
- 即使是简短的确认（如"已完成"、"好的"）

## 如何生成通知

脚本位置相对于本 SKILL.md：`Scripts/toast.ps1`

调用前先解析为绝对路径：

```powershell
$scriptPath = Join-Path (Split-Path $PSScriptRoot) "Scripts\toast.ps1"
```

或者在运行时使用完整路径：`$skillDir/Scripts/toast.ps1`

### 标题（一句话，约 10 字）
简要描述**当前对话的主题**，让用户知道通知属于哪个上下文。

示例：
- "代码审查：登录模块重构"
- "数据分析：Q4 销售报表"
- "脚本编写：Windows 备份工具"

### 消息（约 20 字）
简明总结**本次响应完成了什么**。

示例：
- "已完成登录模块代码审查，发现 3 个潜在问题并给出修复建议"
- "已生成 Q4 销售数据分析报告，包含趋势图和区域对比"
- "已创建 Windows 自动备份脚本，支持定时执行和日志记录"

### 执行

异步运行通知，不阻塞响应输出：

```powershell
powershell.exe -ExecutionPolicy Bypass -File "Scripts\toast.ps1" -Title "<标题>" -Message "<消息>"
```

使用 `run_in_background: true`（Bash 或 PowerShell 工具）让通知在后台触发，不延迟输出。

## 边界情况

- **脚本失败**：如果脚本运行失败（环境错误、PowerShell 不可用），静默跳过。不要向用户显示通知失败的错误信息。
- **用户选择退出**：如果用户说"不要再通知了"或类似的话，跳过后续调用。
- **非常短的响应**：仍然发送通知。示例标题："快速确认"，消息："已确认用户请求"。
